config-firewall-rule-analyzer

A barrier is read line by line here, the way a firebreak is walked: looking for stretches that repeat, stretches nested inside later ones, and the gaps where everything is let through. The banner photograph for this theme is held pending regeneration, so this page carries the logo and intro photographs only.

Named by the caller, never detected

python3 main.py -f RULE_FILE -t TYPE

Both -f/--file and -t/--type are required. The type (iptables, firewalld, or pfctl) is named by the caller and never detected from the file.

Parsers that keep only a slice

iptables parsing keeps only lines beginning -A, so chain creation lines, default policies, and counters are dropped and chain and policy context is lost. firewalld keeps only each rule's opening line, so a multi-line rule's action never reaches the checks. pfctl keeps lines beginning pass or block.

Three checks, no severity, no remedy

The checks are exact duplicates (one redundancy line per repeat), a textual near-duplicate hint when an earlier rule's text is nested inside a later rule's (text only, never chain, addresses, protocol, ports, or action), and overly permissive for the whole word any or the range 0.0.0.0/0. No severity and no remedy is attached to anything.

The report is the result

Findings and clean files both exit 0, so the printed report is the result. A missing file exits 1, and a file from which no rules parse exits 1.
